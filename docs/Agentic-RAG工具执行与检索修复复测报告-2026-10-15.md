## 修复内容

### 1. 同轮工具调用被延后

原因：通用执行内核默认只执行一轮中的第一个工具；AgentRagHost 未声明可连续执行的独立查询/读取工具。

修复：在 RAG Host 声明 `search_knowledge`、`read_knowledge`、`inspect_retrieval_gaps`、`search_public_sources`、`read_public_source` 和 `read_context` 可批处理。内核仍逐个执行，保留取消、参数、来源发现和预算检查。`submit_rag_answer` 不在批处理名单中，提示词要求提交与查询分轮进行。未改通用内核默认策略。

真实证据：Roof 第一次模型响应的三个本地查询全部执行；强起初测第二轮的五次读取全部执行。所有五个任务的请求数与执行数一致。

### 2. 超时与输出截断

原研究模块将配置中的请求等待时间强制压到 45 秒。现在只有 RAG 使用最高 120 秒，仍尊重用户配置中的更低值；其他研究模式保留原默认。RAG 研究时间预算从 240 秒调整为 480 秒。

精简道具模型上下文，移除重复字段来源元数据；原始目录中的字段证据仍保留。传给模型的是目录字段及适配限制，不宣称是已实投事实。

修复后的强起初测没有超时，但两次响应因输出长度限制被内核拒绝，终止为 `invalid_model_response`。这是新暴露的问题，不能计作成功。RAG 原 1,800 token 输出上限调整为 4,000，配置本身允许 6,000，因此没有突破用户配置。补测成功提交完整结构化结果。

增加语料覆盖反馈：明确当前地图、阵营和经济筛选后是否根本没有数据。强起战术库为空时，不再只让模型盲目改关键词；模型可以选择比赛案例或公网。覆盖数量不代表人数、装备、起点已经适配。

### 3. 联网检索不相关

原来只要 RSS 返回条目就标记 `found`，即使全是官网、商店或百科首页。

现在执行以下流程：

1. 避免重复堆叠 CS2、地图和阵营前缀。
2. 对标题、摘要和 URL 做地图与目标关键词筛选；未通过的结果不会作为有效线索交给模型。
3. 没有相关网页且搜索预算尚有余量时，使用项目已有的 Agent-Reach/YouTube 公开元数据搜索；每个后备请求仍占用原搜索预算。
4. 后备结果也经过同样筛选；没有相关来源时返回 `no_relevant_results`，不冒充教程已找到。
5. 搜索只是线索，模型必须另行调用读取工具才能引用；读取视频说明不等于观看画面。未下载视频、未读取账号或浏览器登录信息。

公开诊断中，Bing RSS 的多词查询仍反复返回主要匹配首词的结果；更换空格编码、加引号、加站点限制均未解决。Bing HTML 同样跑题，Google 普通 HTML 返回脚本提示，DuckDuckGo 测试连接失败。不能确认搜索服务内部原因，因此采用已实际可用的视频搜索通道，而不是声称修好了外部 Bing 服务。

### Roof → Heaven

模型先并行提出三个库的查询（工具顺序执行），然后读取 Heaven 道具目录。发现精确站位/瞄点缺失后，主动两次公网补查，并读取一个本地战术来源后提交。

最终明确：已知来源标签为 `Running`、`Jump Throw`；没有精确瞄点、出手时序、单人配合条件。没有生成虚假的坐标或稳定动作。该题 v2 公网未补齐缺口；没有用 v3 视频后备通道重新验证它。

### 三人配合强起转 Ramp

v3 模型根据空库覆盖情况跳过无匹配的强起战术卡，检索比赛案例和道具，读取：

- 外场控制转 Secret 三人下 B 主攻；
- 弱枪五人大厅集结，经控制室转斜坡；
- Outside Cross Smoke 的目录字段。

最终说明五人案例不能直接当作三人方案，列出枪械、烟闪、敌方站位和具体道具动作的缺项。引用均能在本次已读证据中逐字找到。

**质量未完全通过：** 用户说的是“只有 3 个人能配合”，并没有说全队只剩 3 人。回答仍说“少 2 人”“你 3 人无充足掩护烟”，把未知的人数/装备条件推成了不足。它也把职业案例的具体秒数作为可借鉴节奏，适用依据不足；Secret 路线只是相邻参考，不是用户所要的 Ramp 解法。报告将这些列为真实缺陷，而非认为引用存在即可证明判断成立。

### Mirage Window

v3 实际链路为：

1. 自主检索三个本地库；lineups/cases 为空。
2. 同轮检查缺口并调用公网搜索 `Mirage T spawn window smoke solo lineup`。
3. 网页层 10 条结果全部被过滤；YouTube 后备返回的线索中 4 条通过地图/目标筛选，另 1 条被过滤。
4. 模型自行读取 `Every Mirage Instant Window Smoke in CS2 - NEW Updated Lineups` 的视频元数据和说明。
5. 提交两条带引用判断，说明仍无法确认完整瞄点和出手动作。

实际来源：[Mirage Window 教程视频](https://www.youtube.com/watch?v=K38ic2FghXo)。已读说明包含 Spawn 章节、Standard/strafe 等章节，以及多个 `setpos/setang` 原文。这里只证明来源文字里有这些信息，没有验证它们在当前游戏中有效。

**质量限制：** 回答把视频说明中的章节列表称为“字幕时间轴”，表达不准确；本次读取没有证明获得对应字幕或观察视频画面。词法过滤仍可能保留 CS:GO 历史视频等候选，必须在读取后核对版本，不能把四条线索都算作合格的 CS2 动作教程。
