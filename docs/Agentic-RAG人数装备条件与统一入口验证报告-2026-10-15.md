# Agentic RAG 人数、装备条件与统一入口验证

日期：2026-10-15（America/New_York）；审计日志使用 UTC，日期为 2026-10-16。

## 结果

已修复此前“3 人能配合 → 只剩 3 人”“装备未知 → 没有足够烟闪”的条件混淆。使用当前配置的 **muse-spark-1.3-contributor / api.meta.ai** 完成三个真实对照任务，共 **13 次模型调用**，三组均完成回答；本轮目标条件判断检查均通过。

这只证明三个样本中的人数、装备边界得到改善，不证明任何战术是最优解，也不保证所有自然语言回答都不会过度推断。

网站三个研究模式已合并。玩家直接描述目标，Agent 在同一研究入口里自主选择战术、道具或比赛资料，并决定是否补查。沿用现有工作台 UI/UX；旧研究结果仍可查看。

## 条件如何区分

| 信息 | 含义 | 未提供时 |
|---|---|---|
| 可配合人数 | 当前确认能够协同行动的人数 | 未知，不默认 1 人或 5 人 |
| 全队存活人数 | 当前全队仍存活的人数 | 未知，不从可配合人数反推 |
| 配合成员道具数量 | 仅统计这些配合成员的道具总数 | 各类型分别未知；空白不是 0 |
| 明确填写的 0 | 该统计范围内确认没有此类道具 | 保留为已知 0 |
| 经济类型 | 用户描述的经济标签 | 不能据此推出具体枪械、护甲或烟闪数量 |
| 职业案例装备 | 原回合玩家的装备 | 不属于当前玩家，不能直接套用 |

新增独立的存活人数与道具输入。人数和道具默认留空；输入 3 人能配合并不会填充全队存活人数。服务端拒绝负数、布尔值冒充数字，以及明确的配合人数大于存活人数等矛盾结构化输入。

Agent 每轮观察都包含当前条件及来源边界。新增条件比较工具：对明确的当前数值与待核实的最低数量做比较，结果区分“未知”“低于该假设数量”和“仅数量达到”。模型提出的最低数量只是待核实假设，不能凭工具比较就变成经过证实的战术要求。

模型提交的答案同时保存服务端生成的条件表；前端单独显示已填条件，便于检查回答有没有混淆数据。正文明确说明但未填表单的条件可以由模型引用，必须说明来自用户；本轮结构化条件与正文保持一致，未测试两者互相矛盾的情形。

## 统一入口

- 移除了“战术与比赛资料问答 / 单人道具 / 补齐整套 Nuke 战术”选择。
- 新请求统一进入 Agentic RAG，模型根据需求自行决定查哪些库、读取哪些来源和是否补查。
- 仍保留地图、阵营、经济、起点、动作限制等条件输入，以及可选人数/道具字段。
- 从比赛案例跳转时仍携带案例标识与预填需求；不再要求玩家挑选研究模式。
- 删除了原入口中容易被误当成当前实况的“填入来源最低装备示例”。
- 旧接口和旧结果渲染保留兼容；本轮没有新增训练、自动游戏操作或战术执行器。

界面已在应用内浏览器实际打开检查：没有三个模式按钮，配合人数与全队存活人数分开展示，初始值为空。表单序列化检查确认：空白字段省略、明确的 0 保留、案例标识保留、新请求统一进入 Agent 流程。本轮未额外对“单颗道具”和“整套战术补齐”各做新的付费测试，因此不把入口合并当作这些任务能力已经全面验证。

## 三个真实对照

每组最多 6 次模型调用，总上限 18 次；在用户明确确认新增问题与证据可发送至 api.meta.ai 后运行。没有脚本预设模型的检索和读取顺序。

| 情境 | 调用 | 耗时 | 结果与检查 |
|---|---:|---:|---|
| 仅说明 3 人能配合，存活/装备未知 | 4 | 125.961 秒 | completed；保留未知，没有推断另外两人死亡或烟闪不足 |
| 全队 5 人存活，3 人能配合，装备未知 | 4 | 98.632 秒 | completed；区分两个数量，未从强起标签推装备 |
| 全队 3 人存活且都能配合，0 烟、2 闪，其他未知 | 5 | 183.294 秒 | completed；保留已知 0 与已知 2，其他装备继续未知 |

### 1. 仅 3 人能配合

Agent 自主检索并读取原案例、调用条件比较工具，再提交回答。关键原文：

> “这不证明最少必须5人，且3人能配合不等于只剩3人。原案例开局装备只属于原案例，不能推当前装备。”

未解决条件中明确保留了当前枪械和烟闪火数量未知。对于原案例发生秒数，也说明它们属于原案例，不能直接移植到当前强起局。

### 2. 5 人存活，只有 3 人能配合

关键原文：

> “全队5人存活不能说另2人死亡；当前枪械道具未知，强起标签不能推出具体烟闪数量。”

回答没有把原案例五人行动当作已经证明的最低人数阈值。另两名存活队友是否能承担牵制、断后，保留为待确认，而非假定他们一定会配合。

### 3. 明确 3 人存活，0 烟、2 闪

关键原文：

> “当前仅确认存活3人、可配合3人、三人合计烟0闪2，其余火/HE/诱饵/枪甲未知；强起标签不能推出具体装备，原案例装备只属于原案例。”

回答明确没有烟，但没有把这件事扩大为“无法执行任何 Ramp 战术”。因为并未找到足够证据证明某个具体 Ramp 方案的最低烟闪要求，最终保留整体适配为未知。这是已知库存与未知战术要求的区别。

该题第一次提交的引用不是已读证据中的完整逐字片段，被系统拒绝；模型收到错误后自行修正并重新提交。报告保留这次失败尝试，不将其描述为全程零错误。

## 仍需注意

1. 引用逐字存在只证明来源可追溯，不证明它支撑整句话。第三题关于“用户当前库存”的判断旁仍引用了职业案例库存；当前库存实际来自用户输入，引用的语义对应仍应改进。
2. 条件比较是确定性的数值检查，但模型给出的最低需求必须另有依据。未知最低需求不能因为模型填了一个数字就成为已验证阈值。
3. 当前结构化装备输入只覆盖配合成员的道具总数，尚未覆盖逐人武器、护甲、携包状态和详细站位。正文补充信息可被模型读取，但不应冒充已自动解析的游戏状态。
4. 正文与表单冲突、只在正文给出装备、不同语言和更复杂的条件组合，仍需扩展题集验证。
5. 三个任务通过不等于普遍消除了幻觉；完整战术可执行性、当前地图实投和胜率仍未验证。
