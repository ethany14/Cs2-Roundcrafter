## 本次交付

网站 `/assistant` 默认入口现在是“战术与比赛资料问答”。新任务使用现有 Eregion AgentLoop，自主选择资料库、检索词、读取对象及是否补查公开来源，最后提交带来源引用的回答和未解决问题。

这次没有训练模型，也没有更换向量服务或复制 API 密钥。继续使用网站已有的模型配置和向量检索设置。

原“查询一颗单人道具”“补齐整套 Nuke 战术”和比赛案例批量教学继续保留原工作流；底层关键词/向量检索器仍可单独使用。旧 `/api/generate` 的一次性资料选择接口保留兼容。本次升级的是网站默认研究入口，不宣称所有旧接口都已迁移为 Agentic RAG。

## Agent 能做什么

1. 根据问题选择战术简介、道具卡或比赛案例库。
2. 先查询本地，得到结果标题、摘要与证据编号。
3. 读取具体资料，保存该任务自己的证据快照。
4. 发现缺口后改写关键词、换资料库或搜索公开网页；没有固定的“每个库都查一遍”要求。
5. 使用已有公开来源读取工具与缓存。搜索摘要不能直接作为已读来源引用。
6. 提交中文判断、逐字引用、未解决项和结束原因。

模型可以选择工具，不能改变任务中的地图、阵营或结构化筛选条件。没有逐人装备的通用问答不会假装通过逐人装备检查；已有 Nuke 专用入口继续负责那部分检查。

工具为 `search_knowledge`、`read_knowledge`、`inspect_retrieval_gaps`、`search_public_sources`、`read_public_source`、`submit_rag_answer`。

## 证据与适用性

| 资料类型 | 可提供的依据 | 当前边界 |
| --- | --- | --- |
| 战术库 | 历史标题、简介、地图、阵营、经济标签及已知条件 | 不是经过验证的执行方案；未知装备条件保留 |
| 道具库 | 来源记录、动作标签、字段证据与原视频链接 | 区域推断、历史来源、动作原文分别保留；未认证实投 |
| 比赛案例库 | 已完成解析片段的观察事件与先前模型解释 | 解释仍是模型推断；观战信息不等于玩家已知信息；经济适配未知 |
| 公开网页 | 实际读到的文字与读取范围 | 不等于已看视频画面，也不自动证明地图、站位或装备适配 |

战术库按经济标签过滤，道具库按已有字段检查起点、动作和配合限制。比赛案例缺少可统一硬筛选的经济字段，因此明确标为未知。公网来源需要继续判断适用性，不能仅因搜到就称为当前局势最优解。

每条判断必须引用本次实际读过的证据编号，且引文须为该证据原文中的连续片段。不能引用其他任务的编号，也不能把搜索结果摘要伪装为读过的正文。

**逐字引用校验只能证明引用可追溯，不能自动证明原文可靠、判断与引文语义一致或战术正确。** 最终文字仍标为模型推断，未增加胜率预测或“最高胜率战术”的承诺。

## 预算、保存与故障处理

- 每任务最多 8 次模型调用，最后一次只允许整理提交。
- 最多 6 个不同本地查询、8 条已读证据、24 次受预算约束的研究操作。
- 公开来源最多 3 次搜索、8 次页面读取，复用现有缓存和地址检查。
- 研究时间预算 240 秒；达到时限后只允许最后整理，已经发出的请求仍有各自超时。
- 重复本地查询复用已保存结果；失败查询保留失败状态，不伪装成成功的零结果。
- 查询、证据、轨迹和模型调用数持久化；恢复不会重置调用额度。
- 取消后不接受新的结果；失败或预算耗尽时保留证据，不展示虚构的完成答案。
- 没有配置模型时，仅做明确标识的本地降级检索，不称为 Agent 完成的回答。

向量服务继续沿用既有配置，其模型首次下载、索引构建和向量请求没有独立计入“8 次语言模型调用”；这不是固定费用上限。下一阶段若需要严格费用上限，应统一统计向量与生成服务用量。

## 验证结果

### 自动化验证

新 Agentic RAG、旧道具研究、战术 RAG、案例教学与 Agent 参数处理回归共 **79 项通过**。最后补充时间持久化后，重新执行新模块 **15 项测试，全部通过**。

覆盖：

- 真实 Eregion AgentLoop 配合离线脚本模型：首次检索为空，第二次换库，读取后引用提交；共 4 次脚本模型调用。
- 拒绝未读证据、伪造引文、直接绕过工具结束。
- 保持地图、阵营、经济条件；比赛解释保持推断标签。
- 重复查询缓存、失败查询记录、查询额度、取消和模型预算。
- 恢复后预算不重置、模型失败时保留已读证据。
- 无模型配置的本地降级，以及外部来源发现/读取/引用的离线契约。
- 原道具研究与案例教学回归。

JavaScript 语法检查与 Git 空白检查通过。

## 使用方式

1. 打开 `http://127.0.0.1:8790/assistant`。
2. 选择默认“战术与比赛资料问答”，填写地图、阵营、经济、人数以及问题。
3. 点击“开始检索并整理”，开始使用已配置的模型；按需要产生公开搜索和向量请求。
4. 查看“检索过程与来源读取”，展开每条判断的引用，检查仍需确认的条件。

例如：“Nuke T 方强起局，三个人能够配合。请找外场牵制转 Ramp 的参考，检查哪些道具和配合条件还不清楚。”

## 接下来建议验证
