## 实现与现有核心的关系

新增 backend/cs2_agent/demo_coach.py，CoachHost 继承现有 WorkspaceHost，实际循环仍由原 Eregion AgentLoop 执行，模型传输复用 ConfiguredModel。没有另建聊天机器人，没有训练模型。

流程：规则构建带稳定编号的行动证据 → read_round_evidence → read_action_window → submit_analysis → 引用及规则检查 → 本地复核 → 页面显示。真实模型调用使用已配置 api.meta.ai，且只在用户明确确认四回合数据外发后执行。未发送原始 demo、玩家姓名或账号。

本地取证保留至少1秒的稳定区域段，过滤死亡后的移动记录；提取每人首次稳定进入包点及前一稳定区域、15秒人员分布、道具、击杀、下包。假设以这些证据生成：先后进入、8秒内集中进入、多入口汇入、进点前道具时序、下包阶段。入口是前一稳定区域，不等于已人工确认的具体门线。

提交时核对假设存在、引用集合、对应的玩家和时间窗口。未先读取回合与详细窗口不得提交；错误最多两次修正。自然语言解释与原始事实分别呈现。自动检查主要覆盖结构、引用及确定性条件，不是完整自然语言事实证明器；本轮四个回合另做了逐条审阅和纠正。

空间关联新增保守门槛：道具与进点位置的XY距离不超过1400单位；烟/火高度差不超过160。此为产品筛选规则，不是游戏作用半径或可见性测试。Nuke R24 三次发生于另一位置/楼层的道具被排除出A点进点关联，原始事件仍保留。

## 2D 页面

主面板显示一句话摘要和逐条解释，每条同时显示证据文字、引用验证范围、播放按钮。按钮使用程序从证据生成的时间范围与玩家集合，不接受模型任意指定播放坐标。

播放时高亮相关玩家与轨迹、弱化其他人，片段末尾自动停止；Nuke 根据相关玩家位置自动切换楼层。旧规则和长串原始记录折叠。四个试点有独立链接，链接保留回合编号。试点以外不触发模型分析；原上传解析和实验室保持独立。

## 失败、修复与真实验证

- 首次模型调用被自动审批拒绝：缺少具体比赛数据发往具体端点的授权；等待用户确认后才执行。
- Nuke R13 首次5次调用因重复窗口取证和上下文读取耗尽，没有生成解释；如实保留用量。修复阶段门禁、压缩窗口、提供当前阶段证据后，用户另授权3次，最终完成。
- Dust2 R17 已产出真实解释，但 alternatives 返回对象数组而原工具要求字符串，触发格式拒绝及后续输入预算耗尽。本轮从原始真实响应做本地归一、引用校验，未额外调用模型；移除一处未绑定引用的结局描述。工具格式已修正。
- 修正了清理 Host 时设置取消事件导致状态被误写为cancelled的问题；修正片段舍入越过回合末尾与试点链接回合参数丢失。
- 对单帧开局分布进行了文字澄清：10–20秒是播放范围，观察事实来自15秒快照，不能描述成10秒内一直保持该站位。
- 测试：demo_coach、demo_review、core_migration、free_lab 共60项通过。包含伪造引用拒绝、取证门禁、取消后不提交、持久预算不能重置、跨区域道具排除、四个真实结果引用与时间边界，以及原Eregion和实验室回归。
- 本地模型桩仅用于工具循环测试。上述四回合的解释另有真实 provider usage 及 Agent transcript，不以测试桩替代实际调用。
- 浏览器验证：真实解释显示；Nuke R13 单人进点片段自动切至下层并停在27.25秒；Dust2 R17 四人片段从74秒播放至95秒自动停止。涉及玩家透明度1，非涉及玩家0.25。
- 完成结果再次启动命中缓存，不产生新模型调用。

## 用量与边界

真实模型总调用19次；服务返回的输入 tokens 50313，输出 tokens 23444（含服务统计口径中的推理部分）。包含首次失败流程，并非只计算成功结果。金额没有可核实的计价依据，未估算。

每回合默认总上限5次，Nuke R13 依据用户追加授权持久化为8次；重新启动不会清零。单次请求45秒、输出上限2200 tokens；单轮分析180秒、输入预留上限50000；支持取消和丢弃取消结果。应用没有搜索、页面读取或额外外部服务调用。

详细记录：demo-coach-verification.json。原始任务状态、工具交换和usage.sqlite位于各比赛目录的coach-agent-*子目录；复核前结果保留在pre_audit_result，未覆盖原始demo与轨迹。
