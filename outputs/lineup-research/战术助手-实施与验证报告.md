## Agent-Reach 接入与实测边界

按用户最后的指示采用 [Agent-Reach](https://github.com/Panniantong/agent-reach)，未将早先提出的独立 Bilibili MCP / YouTube Data API 方案安装进项目。固定版本为 `94f06c1969dfc1834001269d79d3ad0972d9dee6`，Agent-Reach 1.5.0、yt-dlp 2026.8.19、bilibili-cli 0.6.2。该项目是能力路由层，实际读取按其文档直接调用上游工具；没有虚构一个 `agent-reach read` 接口。

- **YouTube**：真实视频搜索返回候选；六个原始教学视频的标题和说明均成功读取，说明中的 MetaStack 回链可与旧条目核对。六个原视频均未取得字幕。没有观看画面，不能将视频标题或“这是教程”的宣传说明当作具体动作。
- **Bilibili**：无登录搜索真实返回视频候选。独立应用适配器测试读取 `BV1Nx4y1m7ei` 详情被 HTTP 412 风控拒绝；没有绕过挑战，也没有把该结果升级为适配投法。字幕浏览器渠道本轮未启用。
- **网页**：应用 HTTP 读取 CS2.app 首页成功，实际取得 3348 字符可见文本；公开 RSS 搜索实测返回 10 条线索。首页可读不代表某个投法动作已核验。
- **MetaStack**：直接 HTTP 读取被 403 拦截；Jina 可返回文字，但六条先导页面得到的主要是 Cookie 提示/缺少教学正文，最终按证据不足处理。早期试跑曾把这种文字标为“read”，审阅中发现并修正，保留该早期记录，不以它统计教学核验成功。
- 上游 scoped doctor 只检查 YouTube/Bilibili 的本体运行；不会证明具体内容可读。应用逐次实际结果才是验收依据。yt-dlp 的 Node JS runtime 由每次命令显式传入，不写全局配置。

应用没有依赖开发会话的 Codex 搜索工具完成这些任务。没有人工打开或输出密钥；应用仅使用既有模型配置进行鉴权。未读取浏览器 Cookie，未登录、发评论、点赞、下载音视频、训练新模型或调用付费转写。

## 测试、失败分流与浏览器

最终运行 **72 项测试全部通过**（新助手 35 项，现有 Nuke/检索/Eregion 相关回归 37 项），耗时约 3 秒。测试桩仅用于离线合同和约束验证，不算真实联网验收。另执行 JavaScript 语法检查和浏览器实际交互。

测试覆盖：六条迁移逐字段等值；中英文别名；错误地图/目标/起点/阵营/动作/道具；配合人数不足；逐人库存不足；未知库存；缺坐标但有视频；来源字段冲突；搜索摘要不能成为事实；引用必须来自实际读取正文；不能提交坐标/虚假实投字段；私网 URL 拒绝；去重缓存；预算和取消；Eregion 阶段、调用预算及持久化；视频命令禁止私人配置和 Cookie；Bilibili JSON 结构；缓存身份不改写实际传输域名。

失败码分别保留 `not_found`、`inaccessible`、`insufficient_evidence`、`incompatible`、`search_unavailable`、`budget_exhausted`、`cancelled` 和模型/运行失败。`not_found` 只表示预算内暂未找到；搜索或页面拦截不等于资料不存在。网络预算耗尽时仍可整理已经得到的卡片和缺项。最终 Heaven 任务中，模型曾尝试本阶段未授权的 `read_context`，被 Eregion 拒绝；未取得额外数据或触发外部调用，随后继续整理并在 6 次调用上限内结束。这一失败没有隐藏为成功工具调用。
