# 残局三维站位与当前队伍经济

日期：2026-10-13。21 个已有评审场景、七张地图。所有数据在本机解析，没有付费模型调用。

## 打开与操作

[打开本地三维评审页](http://127.0.0.1:8789/)。服务停止后，在工作区运行 `start-strategy-review.ps1`。

选择案例后可旋转、缩放、俯视、聚焦自己，并按原始 Z 高度剖切地图。自己为金色、队友为蓝色；人物标记穿透显示以便定位，不代表游戏中的实际可见性。X/Y/Z 保留游戏坐标，渲染使用 X/100、Z/100、−Y/100，未自动猜测楼层名称。

默认仅加载己方站位与自身点亮或历史报点。敌方当前真实坐标在单独接口中；点击观战按钮才请求，当前案例会永久标记已查看观战信息（本机浏览器记录）。这项标记辅助人工纪律，不是防篡改安全机制。Nuke case-19 在本轮界面验证中已标记为观战；没有填写任何人工战术评分。

## 当前队伍经济

从同一 demo、同一 tick 读取全队五名成员的 balance、start_balance、cash_spent_this_round、current_equip_value，以及血量、护甲、拆包器、当前武器、背包。身份使用 CT1–CT5，不展示 Steam ID。

队伍现金包括阵亡成员；可保留装备仅汇总存活成员。阵亡后的装备字段可能仍保留旧值，不计入可保留装备。余额会受本回合奖励等影响，因此不能仅用回合开始余额减花费推算当前现金。连败奖励与下一回合收入仍未知，未伪造下回合购买力。

当前评审集的视角都是 CT。该页不是双方财务透视，也没有把敌方真实站位交给策略模型。Agent 的 inspect_postplant_strategy 已为这 21 个注册场景补充当前队伍与经济字段；原模型仍使用原训练输入，本次未重训。

## 核验

- 全部 21 个场景均有五人名单、唯一自身匹配、有效三维坐标；现金求和和存活装备求和通过检查。
- 相关 Python 测试 4 项通过；JavaScript 语法检查通过。
- 浏览器实际检查 Anubis 和 Nuke；Nuke 的 1v4 场景显示四名敌人的观战标记、不同 Z 高度与 CT 全队 $800 现金、$4,550 存活装备。
- 检查地图高度剖切与观战退出盲评标记。评审记录可保存在浏览器并导出 JSON；未代替用户填写评分。
- 修复了离线 Windows 下 HTTP 服务启动时反向 DNS 查询可能阻塞的问题。

## 限制

地图仍是本地静态碰撞几何，未完整恢复动态门、烟雾、火焰和可破坏场景；包位置来自已有“明确报点”假设，40 秒计时也仍是场景假设。这是一帧局势定位工具，尚未播放连续动作。21 个片段都是下包后片段，其中也有敌方已全部阵亡但仍待拆包的片段，页面会显示实际人数。不能仅据该几何页认定某条路线安全或某方案最佳。
