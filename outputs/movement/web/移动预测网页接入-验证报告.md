# 小型移动预测模型：网页接入与验证报告

日期：2026-10-14。全部推理在本机 CPU 运行，没有调用任何外部 LLM，没有重新训练、没有下载模型，也没有改动历史训练产物。

- **网站入口：** http://127.0.0.1:8790/demos ，打开任意一场比赛的回放，右侧面板选择 **「移动预测」**。
- **启动方式：** `./start-tactics.ps1`

## 1. 使用的模型（核实结果）

| 项目 | 内容 |
|---|---|
| 模型 | `movement-numeric-gru`：数字时序模型 A 组（`outputs/movement/comparison/numeric-{7,17,29}.pt`），三个种子取平均 |
| 训练 | 2026-10-13；77 份职业 demo，7 张地图；按系列赛划分 19/5/6 场（训练/验证/测试）；按验证集 ADE 选 checkpoint |
| 结构 | GRU(8→48) 读 5 帧历史，与 16 维上下文拼接后接 MLP，输出 6 维；12,902 个参数 |
| checkpoint SHA-256（前 16 位） | numeric-7 `e3cd5be821bc6780` · numeric-17 `1612d0841edd5a03` · numeric-29 `52a53bb16a965095` |

我检查了磁盘上全部四组权重，选择这一组的理由如下：

| 权重组 | 移动 ADE | 结论 |
|---|---:|---|
| `comparison/numeric`（本次采用） | 63.09 | 移动误差最低，输入可以从 demo 完整重建 |
| `comparison/qwen_adapter`、`fusion` | 69.59 / 68.91 | 比数字模型差，而且需要 4B LLM 特征 |
| `joint/original`、`enriched_move`、`joint` | 63.09 / 63.12 / 63.20 | `original` 是同一结构的重训版本；另外两组在移动上没有改善 |
| `environment/environment_joint` | 63.44 | 依赖 42 维环境重建（声音、碰撞、烟火视锥），网页端无法低成本可靠复现 |

README 里提到的 `movement-seed-*.pt` 在磁盘上不存在，所以没有使用。

### 开枪、道具输出：核实后决定不展示

联合模型（`joint`、`environment_joint`）确实还会预测六类动作。根据它们的验证报告：

- **开枪：** AP 0.069，低于「重复最近动作」基准的 0.161；加入环境信息后为 0.226，但移动误差变差，且测试集已经被查看过。
- **道具：** 测试集正例只有 0–23 个（烟 15、闪 23、雷 7、火 14）。
- **诱饵弹：** 训练集正例为 0。

因此这些输出没有接入网页，只在面板的「模型说明与限制」里说明原因。

## 2. 输入与输出

输入与 `experiments/movement/extract.cjs` 训练时的提取方式逐项一致。

- **采样：** 64 tick；以 32 tick（0.5 秒）为一帧，取当前时刻及之前 4 帧，共 2 秒历史。网页把所选时间对齐到 0.5 秒。
- **历史 `h[5×8]`：** 每帧 8 个值。
  - 以当前视角朝向旋转的相对 X/Y（÷250）和相对高度（÷250）
  - sin/cos 朝向变化、pitch/90、蹲伏量、闪光秒数/5
- **上下文 `c[16]`：**
  - 血量/100、护甲/100、是否 CT
  - 回合秒数/120、我方/敌方存活数/5
  - 是否已下包、下包经过秒数/40
  - 最近两名存活队友的相对位置（±12 截断）、相对高度和「在场」标记
- **数值处理：** 按 `prepare_comparison.py` 保留三位小数。模型没有额外的归一化文件，缩放全部写在特征公式里。
- **不使用的信息：** 敌人隐藏坐标、玩家身份、地图绝对坐标、未来事件、胜负。
- **输出：** 未来 +0.5 / +1 / +2 秒的水平位移，单位为朝向局部坐标 ×250 游戏单位。网页把它旋转回世界坐标，再按雷达公式 `px=((x−pos_x)/scale, (pos_y−y)/scale)` 画到地图上。
  - 模型**不预测高度**。预测点沿用起点高度，因此画在起点所在楼层。
- **适用条件：**
  - 7 张训练地图（ancient、anubis、cache、dust2、inferno、mirage、nuke），64 tick
  - 此刻 demo 中正好 10 名玩家
  - 玩家在过去 2 秒内持续存活，同阵营、同回合，且没有超过 200 单位的跳变

### 缺失输入一律拒绝，不补零

接口返回 HTTP 422，并附带稳定的错误码，网页显示中文或英文原因：

| 错误码 | 含义 |
|---|---|
| `unsupported_map` | 地图不在训练范围内 |
| `unsupported_tickrate` | tick rate 不是 64 |
| `insufficient_history` | 回合开始后不足 2 秒 |
| `history_missing` / `not_alive` / `field_missing` | 历史帧缺失、玩家未存活或字段缺失 |
| `teleport` | 历史中出现超过 200 单位的跳变 |
| `not_ten_players` | 此刻不是 10 人对局 |
| `history_crosses_round` | 历史窗口跨越换边或回合边界 |
| `demo_missing` / `players_missing` / `model_missing` | 缺少 demo 文件、玩家映射或模型文件 |

唯一的例外是存活队友不足两人。此时按训练时的编码写 `[0,0,0,0]`（「在场」=0），这正是模型训练时见过的「队友不存在」状态，不属于补零。

## 3. 实现

| 文件 | 作用 |
|---|---|
| `experiments/movement/window.cjs` | 用与训练相同的 demoparser2、回合配对和 tick-rate 检查，读取回合边界和指定 tick 的玩家原始字段 |
| `backend/cs2_agent/movement_model.py` | 特征构建（`extract.cjs` 的 Python 移植，只接收历史帧）、三种子集成推理、坐标还原、真实后续读取、误差计算；回合边界缓存在 `outputs/demo-review/<id>/movement-v1/` |
| `backend/cs2_agent/tactics_server.py` | `GET /api/movement/info`、`GET /api/movement/predict?id=&round=&t=&player=` |
| `web/movement.js` | 回放右侧「移动预测」面板，以及回放画布上的叠加层 |
| `web/replay-engine.js` | 新增 `overlay` 绘制钩子（复用现有 2D 回放组件） |
| `experiments/movement/evaluate_web.py` | 用网站同一条代码路径做整场评估 |
| `tests/test_movement_model.py` | 11 项测试 |

### 防止真实后续泄漏进输入

`predict()` 先只读取 t−2s…t 五帧并完成推理，之后才单独调用 `actual()` 读取 t+0.5…t+2s。

测试 `test_future_track_never_reaches_the_model` 把未来轨迹整体平移 500 单位，验证预测结果和输入特征完全不变，而真实轨迹随之改变。

### 网页展示

- 面板标题旁标注「模型预测 · 非最优路线」，起点标注「模型预测 · 起点」。没有使用「最优路线」「AI 推荐」等字样。
- 地图上的图形：
  - 灰色虚线：过去 2 秒
  - 琥珀色虚线：模型预测，终点标「+2s」
  - 绿色实线：demo 真实后续，可以关闭
  - 蓝色点线：匀速外推基准，可选
- 面板给出三个时间点的误差，与「匀速外推」「原地不动」对照。
- 如果这场 demo 属于训练或验证数据，面板会提示误差偏乐观；属于测试集时，会注明该测试集之前已被查看过。
- **楼层：** 预测后自动切换到起点所在楼层（Nuke 的分层线是游戏自带的 z = −495）。每个点按自身 z 判断楼层，只在对应楼层绘制。真实轨迹跨楼层时，面板会提示切换楼层查看。
- **「▶ 回放这 4 秒」：** 从 t−2s 播放到 t+2s。

## 4. 验证

### 4.1 推理一致性

| 检查 | 结果 |
|---|---|
| 从原始 demo 重新提取 30 个随机测试样本 | 30/30 的 `h`、`c` 与训练数据 `comparison/data.npz` 一致（误差 ≤0.0015，即三位小数取整误差） |
| 这 30 个样本的网页推理结果 vs 训练时保存的 `test-predictions.npz` | 最大差 0.056 游戏单位（GPU 与 CPU 的浮点差） |
| 测试 `test_matches_stored_test_predictions` | 用 64 个测试样本复核，通过 |

### 4.2 整场端到端误差

`evaluate_web.py` 在每回合每 2 秒取一个时刻，对所有存活玩家做预测，并只保留真实后续完整的窗口。

| 数据 | 窗口数 | 模型 ADE | 匀速外推 ADE | 原地不动 ADE |
|---|---:|---:|---:|---:|
| 测试集全部 16 场（6 个系列赛） | 101,821 | **65.2** | 71.7 | 100.9 |
| 其中 Nuke（3 场） | 19,534 | 65.6 | 72.2 | 99.9 |
| 其中 Dust2（3 场） | 20,895 | 65.9 | 70.7 | 97.6 |
| 网站上的 Nuke 比赛（训练集） | 8,558 | 66.2 | 72.3 | — |
| 网站 Dust2 比赛（测试集，fa2dea5f） | 6,525 | 66.3 | 72.0 | — |

单位是游戏单位，越低越好。

- **与原报告的关系：** 原报告是在 1,024 个抽样窗口上得到 63.09。本次是测试比赛的全部窗口，65.2 与之相符。
- **样本层面：** 模型只在 53–61% 的窗口上优于匀速外推。平均优势主要来自减速、转向这类匀速假设出错的场景，并不是每个片段都更准。
- **Nuke 跨楼层：** Nuke 测试窗口中，有 332 个在 2 秒内跨越楼层，这些窗口的 ADE 为 98–107，明显差于整体，因为模型不预测高度。
- **训练集 demo：** 网站上属于训练集的 demo 误差并不比测试集低（66–72）。原因是每场训练 demo 只抽了 64 个窗口参与训练，但网页仍然会对这类 demo 标注「误差偏乐观」。

| 由静止起跑 | Nuke / 训练 | R1 14.0s xertioN | 33 / 119 / 321 | 158 | 163 | 162 | 327 | −128 → −81 |
| 爬梯子（比匀速差） | Nuke / 训练 | R1 6.0s xelex | 75 / 175 / 336 | 195 | 153 | 54 | 64 | −416 → −124 |
| 中位数片段 | Nuke / 训练 | R19 12.0s tN1R | 42 / 45 / 74 | 53 | 55 | 136 | 178 | −416 → −361 |
| 最大误差 | Dust2 / 测试 | R12 22.0s KSCERATO | 164 / 363 / 678 | 402 | 354 | 218 | 382 | 19 → −9 |
| 探头回撤（第 90 百分位） | Dust2 / 测试 | R6 24.0s FalleN | 65 / 193 / 166 | 141 | 225 | 49 | 46 | 41 → 20 |
| 中位数片段 | Dust2 / 测试 | R4 26.0s flameZ | 3 / 42 / 112 | 53 | 50 | 50 | 113 | −108 → −112 |

Nuke 片段的比赛编号为 `3f9df19a…`，Dust2 为 `fa2dea5f…`。截图：`nuke-r3-floor-change.jpg`、`dust2-r6-peek-return.jpg`。

**观察：**

- **方向突变：** 两个最大误差片段，都是玩家在高速移动中突然反向。模型按惯性和职业平均行为外推，2 秒终点误差达到 680–820 单位。其中 Nuke 片段还从上层（z −422）掉到下层（−640），真实轨迹的后半段需要切换到下层才能看到。
- **爬梯子：** 玩家 2 秒水平只移动了 64 单位，高度却上升了约 290。模型只预测水平移动，因此误差远大于「原地不动」。
- **探头回撤：** 玩家探出后马上收回。模型预测持续前进，「原地不动」反而更准。
- **静止起跑：** 历史里没有起跑信号，模型和匀速基准都预测原地附近，误差同样很大。
- **中位数片段：** 误差约 53，与匀速基准相当。

## 5. 已知限制

1. 这是职业选手行为的统计预测，不是最优路线，也不是决策建议。它不知道敌人在哪，不知道地图几何（路径可能穿墙），也不知道烟、火、闪的效果。
2. 不预测高度和楼层。楼梯、梯子、掉落等跨层移动误差明显更大（Nuke 跨层窗口 ADE 约 100）。
3. 只覆盖 7 张训练地图、64 tick、10 人状态、过去 2 秒持续存活的玩家。不支持的情况会明确拒绝，而不是降级运行。
4. 网站上的 7 场比赛中，5 场在训练集、1 场在验证集，只有 `fa2dea5f`（Dust2）属于测试集。测试集在之前的实验中已被查看过，所以这里报告的误差都不是全新独立数据上的确认性结果。
5. 训练数据只包含整个 4 秒窗口都存活的样本，因此不能评估「这样走会不会被打死」。
6. 只用 0.5 秒采样，无法描述急停、拉枪等几十毫秒级的操作。
7. 开枪、道具动作预测未经验证合格，没有展示（见第 1 节）。
8. 每次预测需要从 .dem 读取 5 个 tick，约 1–3 秒。首次打开某场比赛时，还要额外约 1.5 秒建立回合边界缓存。

## 6. 复现

```powershell
$env:PYTHONPATH='backend'
./.venv/Scripts/python.exe -m pytest tests/test_movement_model.py -q
./.venv/Scripts/python.exe experiments/movement/evaluate_web.py   # 输出 outputs/movement/web/evaluation.json、site-cases.json
```

| `test-clips.json` | 上表 7 个片段的接口原始结果 |
