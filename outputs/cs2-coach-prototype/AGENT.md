# 自动复盘 Agent

CS2 项目独立实现的 Node.js Agent，不导入 Eregion/JobHunterAgent 工作区、Python 环境或配置文件。运行仅依赖本项目和已安装的 demoparser2。

## 默认流程

导入 demo → 本地解析 → 后端自动排入复盘队列 → 模型选择工具 → 检查片段/回合 → 结构化提交 → 校验引用与玩家归属 → 页面显示总结和最多 3 个训练重点。

无需输入问题。页面关闭后任务继续；刷新读取保存结果，不会重复调用已经完成的同一任务。失败不自动重试，可手动重试。停止、超时、调用上限、服务中断均保留明确状态。首次真实联调发现较长报告会被截断，因此当前要求精简报告；截断结果不会发布。

默认分析全场，用 P1/P2 区分玩家；尚未绑定上传者 Steam ID，不能把全场重点当作同一个人的评价。网页将代号映射回本地玩家名称。自动训练项默认安排为 10 分钟，是应用预设时段，不是模型测量结果。

## 配置与调用预算

日常工作区只读取 `Cs2-agent/.env`；源码 ZIP 单独解压后读取解压目录 `.env`。不会读取进程中继承的 LLM 密钥或扫描其他工作区。

必填：`LLM_BASE_URL`、`LLM_MODEL_ID`、`LLM_API_KEY`。地址填兼容 API 根地址（通常以 `/v1` 结尾），也支持完整 `/chat/completions` 地址；模型必须支持 function tools。

配置在创建任务时重新读取，无需因改密钥重启。配置不足时显示“等待模型配置”。`CS2_AUTO_REVIEW=false` 关闭新任务，运行中的任务用页面“停止本次复盘”结束。

默认每次任务最多 6 次调用、每次输出上限 6000 tokens、超时 180 秒、无网络自动重试；截断最多用已有证据重写一次，仍计入总调用上限。`LLM_TOKEN_LIMIT_FIELD` 默认 `max_tokens`，部分服务需要 `max_completion_tokens`；可选 `LLM_AGENT_REASONING` 仅在服务支持时填写。单次请求文本限约 160 KB，响应限 2 MB。费用按你配置的模型服务计算。

## 数据与限制

原始 demo 本地解析。模型上下文仅包含匿名玩家代号、统计、事件、位置快照及死亡/伤害/致盲时间线，不含 Steam ID、昵称、原始文件或用户笔记。API key 只用于对指定服务认证，不进入模型上下文、报告或浏览器。

仅提供 `inspect_findings`、`inspect_round`、`submit_review`，没有运行命令、读取任意文件或浏览外网的工具。初始最多列出 100 个候选，按玩家和类型轮流抽取；回合时间线可分页。报告标明总候选数和实际检查数。

提交校验覆盖 JSON 结构、引用存在、证据已读取、玩家归属；这不等于验证了自然语言因果推断。模型仍可能误判。当前没有地图遮挡、可见性、语音和战术意图，不提供精确准星评分或职业级战术结论。

这是有预算的自主工具调用循环，尚无跨场长期记忆或中断后逐步续跑。服务重启将未完成任务标为中断；手动重试重新运行。报告、工具动作摘要、服务返回的 token 用量保存在 `data/reviews/`。

工具调用格式参考 [OpenAI 官方 function calling 文档](https://developers.openai.com/api/docs/guides/function-calling)，实际调用你在 `.env` 中指定的服务。
