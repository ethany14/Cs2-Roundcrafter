# CS2 助手：参考产品与首个工具模块

研究日期：2026-10-12。目标是为 CS2 Agent 做出第一个可用模块，从成熟产品借鉴基础流程，逐步扩展；不是复制 Refrag，也不要求首版具备独家能力。

更新：后文记录 0.1 的调研与技术取舍。0.2 已按用户要求独立实现自动复盘 Agent，不引用原工作区；配置、数据流与费用以 `AGENT.md` 为准。

## 查到的功能与取舍

以下来自官方公开产品页与文档，未购买或实测其付费能力。“值得借鉴”是本项目的产品判断，不表示已恢复其实现。

|---|---|---|---|
| [Skybox EDGE](https://skybox.gg/edge/) | 2D 回放、统计、模式查找、战术本、赛前准备与语音整合 | 按回合定位证据，个人视角和团队视角共用比赛数据 | 先做事件筛选、位置快照；完整回放和战术模式识别后续做 |

## 为什么暂缓精确准星评分

玩家位置和 yaw/pitch 能显示朝向，但不足以可靠判断准星是否预瞄正确：需要地图遮挡、敌人可见性、模型命中盒以及明确采样口径。Leetify 的[2026 年命中盒与枪法统计改进说明](https://leetify.com/blog/aim-stat-calculation-hitboxes-improved/)介绍了自有射线检测、可见性与命中盒处理对指标的影响；其[指标说明](https://leetify.com/blog/leetify-stats-glossary/)也可作为定义参考。第一版先显示原始朝向供人核查，之后单独建立测试集再开发评分。

## REA 实际做了什么

使用 [morluto/rea](https://github.com/morluto/rea) 的 npm 发行版 `rea-agents@6.4.0`，调用 `analyze-javascript-application`：

1. 静态分析了 Skybox EDGE 公开页面取得的 HTML 与一个 18,882 字节的同源脚本。结合源码检查，内容主要是轮播、标签切换、页面滚动与价格展示交互。未获得其 demo 分析或评分逻辑。
2. 静态分析了开源 `@laihoe/demoparser2@0.42.0` 的 JS 包，核对了原生绑定和接口。REA 输出中的静态关系不是运行证明；随后以公开真实 demo 实际验证了解析器。
3. Leetify 与 PRACC 部分脚本下载返回 403，未取得该部分代码。本研究对其功能的判断来自公开官方页面。

证据 ID、哈希、统计、限制见 `rea-evidence-summary.json`。REA 的“electron-renderer”等通用分析分类不构成 Skybox 使用 Electron 的证据。我们没有反编译原生解析器，没有取得竞品私有服务端实现，也没有将竞品专有脚本加入产品。REA 可以辅助理解拿到的产物；它不能从营销页面恢复远端服务。

## 可运行首版

数据链路：`.dem → demoparser2 → 事件与死亡前快照 → 规则候选片段 → 人工复盘判断 → 训练项`。

已实现：真实本地 demo 导入、逐玩家/回合筛选、队友致盲、雷火对敌伤害、死亡前携带道具、位置朝向快照、笔记、训练记录、JSON 导出、同地图同玩家事件量比较。

这些片段是回看线索，不能自动等同于失误。例如死亡时还有烟不代表这颗烟应该更早扔出；故意牺牲部分队友视野也可能属于配合。保留玩家判断，是为了收集未来有用的训练反馈。

样例来自 [demoparser 公开测试 demo](https://github.com/LaihoE/demoparser/blob/main/src/parser/test_demo.dem)，生成结果经过玩家匿名化。包含 10 名玩家、10 个可观测回合和 47 个候选片段，不是职业水平基准。

## 如何继续接 Eregion Agent

当前提供独立解析模块与 `agent-contract.json` 接口提案，尚未修改或接入 Eregion 项目。

1. 在 Eregion 注册本地工具，调用 `analyzer.cjs`，让 Agent 能读取 report、finding ID 与 tick。
2. Agent 用结构化证据组织解释、询问玩家当时意图、记录训练重点；不把全局敌人位置当成玩家当时已知信息。
3. 保存“候选片段 → 玩家纠正 → 训练执行 → 后续比赛”的记录。先用人工反馈验证规则，再决定是否需要专门模型。
4. 下一批功能建议依次为：按投掷实体聚合道具效果、投掷起点/落点与时机；然后选择一张地图验证准星与可见性；最后扩展交易击杀、协同进点与语音复盘。

首版无需 GPU、模型训练或付费 API；用现有电脑本地运行没有新增云计算费用。主要投入是开发、适配 demo 版本和人工验证。若以后接云端 LLM、服务器或大规模数据存储，才新增相应费用。

## 验证边界

测试覆盖敌友判断、自闪/热身过滤、死亡前背包、伤害统计及真实样例引用。真实 demo 用于完整导入检验。尚未广泛验证不同 CS2 版本、赛事规则、重连和截断数据；也尚未证明任何建议能够提升竞技水平。
